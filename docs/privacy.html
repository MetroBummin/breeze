개인정보처리방침

시행일: 2026년 9월 23일

Breeze(https://breeze.io.kr, 그리고 같은 코드로 만든 iOS 앱)가 무엇을 받고, 어디에 두고, 언제 지우는지 적은 문서입니다. 코드와 같은 저장소에 있고, 코드가 바뀌면 이 문서도 같은 커밋에서 바뀝니다.

한 문단 요약

계정 없이도 거의 전부 씁니다. PDF·EPUB·기사 본문·사진은 내 기기 안에만 있고, 로그인하면 단어장만 계정에 저장되어 동기화됩니다. 책과 읽던 자리는 기기에 남습니다. AI 뜻을 새로 찾을 때만 낱말과 그 문장 하나가 AI 에게 갑니다. 같은 문장/단어 위치에서 확인한 뜻을 다시 보는 것만으로는 외부 AI를 부르지 않으며, Breeze 계정에는 사용자가 단어장에 저장한 예문이 포함됩니다. 다만 기사 URL 가져오기는 CORS 때문에 Breeze 중계 서버에 그 URL을 요청합니다. 광고·추적기·분석 SDK는 없고, 개인정보를 팔지 않습니다.

1. 로그인하지 않으면

기사 URL 가져오기와 AI/영어 사전 메타데이터 조회를 제외하면, 아래는 전부 브라우저(앱) 안에만 있습니다. URL 가져오기는 CORS를 넘기기 위해 해당 URL을 Breeze 중계 서버에 요청하며, 서버는 받은 HTML·이미지를 저장하지 않고 전달합니다. AI·영어 사전 조회의 범위는 각각 3절·5절입니다.

앱 파일 캐시에는 읽은 내용이 하나도 들어가지 않습니다. 담는 것은 우리 서버에서 온 우리 파일뿐이고, 사전 조회·기사 가져오기·동기화는 이 캐시를 그냥 지나갑니다.

breeze.device 는 이름도 계정도 아닌 임의의 문자열입니다. 로그인 전 AI 무료 횟수를 세는 데에만 씁니다. 브라우저 저장소를 지우면 새로 생기고, 다른 무엇과도 연결되지 않습니다.

브라우저 저장소를 비우면 위의 것이 모두 사라집니다. 그래서 아래의 동기화가 있습니다.

2. 로그인하면 (선택)

로그인은 이메일 주소 하나로 합니다. 비밀번호를 만들지 않고, 메일로 온 링크나 여섯 자리 코드로 들어옵니다. 저장소는 Supabase 입니다.

서버에 두는 것:

  • 이메일 주소 — 로그인 수단이자 계정 식별자
  • 단어장 (words의 계정별 레코드) — 낱말·숙어, 문맥 뜻, 사용자가 저장한 예문, 모르는 정도와 복습 기록
  • 이전 버전 기록 — 기존 암호화 보관함, 읽기 진행도 암호문과 기기 연결 기록은 삭제하지 않고 보존합니다. 현재 앱은 새 책·진행도 기록을 보내지 않습니다.

새 단어장 레코드는 종단간 암호화되지 않습니다. 전송에는 HTTPS를 사용하고 서버의 행 수준 보안(RLS)으로 계정별 접근을 제한하지만, 서버 운영자는 단어장 내용을 볼 수 있습니다. 이전 버전의 암호화 기록은 기존 형식 그대로 보존합니다.

다음은 서버에 올리지 않습니다.

  • PDF·EPUB·TXT 원본 파일과 paras 본문
  • 기사·붙여넣기 글의 본문과 사진
  • 책 표지와 삽화
  • 새 책·읽기 위치 기록

책 파일과 읽던 위치는 각 기기에서 관리합니다.

3. 문맥 뜻을 정할 때

낱말을 눌러 문맥 뜻을 받을 때만 일어나는 일입니다. 로그인 전에는 기기당 정해진 체험 횟수, 로그인 후에는 서버가 정한 일일 사용량 풀 안에서 사용할 수 있습니다. 문장 전체 설명도 같은 AI 사용량 풀을 사용하며 낱말 lookup보다 더 많이 차감될 수 있습니다.

처음 보는 문맥 또는 새 분석이 필요한 경우 — Breeze 서버(server/dict)를 거쳐 생성 AI 제공자에게 다음이 갑니다.

  • 누른 낱말과 화면에 있던 형태
  • 그 낱말이 있던 문장 (클릭 위치를 보존해 최대 2400자). 다시 찾기를 누르면 앞뒤 한 문장도 각각 최대 400자까지 전달합니다.
  • 문장의 영어 token 목록과 사용자가 누른 token index

생성 AI는 word/expression 여부, 저장할 canonical, 현재 문장의 lexical member token, 짧은 한국어 뜻을 반환합니다. 작은 뜻 필에서는 이 최소 결과만 사용합니다.

확인한 문장/단어 위치의 Meaning을 다시 보는 경우 — 기기에 저장된 Meaning을 즉시 보여 줍니다. 이 재사용 자체로 문장이나 저장된 Meaning 후보를 외부 AI 제공자에게 보내지 않습니다. 처음 만나는 문맥이나 사용자가 다시 찾기를 요청한 경우에는 위의 생성 AI lookup을 실행합니다.

단어 상세창을 열 때 — 별도의 생성 AI 요청을 하지 않습니다. 이미 기기에 있는 짧은 한국어 Meaning과 아래 영어 사전 metadata만 표시합니다. 과거 버전에 저장된 ai.note/ai.gloss 값은 삭제 마이그레이션하지 않지만 새 런타임은 사용하지 않습니다.

기기 표시(breeze.device)나 계정 식별자는 한도 확인을 위해 Breeze 서버까지만 가며, 외부 AI 제공자에게는 보내지 않습니다.

생성 제공자 — OpenRouter를 통한 DeepSeek가 기본이고, 실패하면 Google(Gemini)로 대체합니다. 처음 보는 item 또는 사용자가 직접 요청한 새 뜻 lookup에만 사용합니다.

서버에 남는 것 — 한도와 운영 확인을 위한 호출 종류, 사용한 제공자와 모델, 성공 여부, 응답 시간, 토큰 사용량입니다. 표제어, 읽던 문장과 그 지문·앞뒤 단어, 책 제목과 책 지문, 저장된 뜻 후보, AI가 준 한국어 뜻, 사용자가 직접 적은 뜻은 운영 기록에 저장하지 않습니다.

하루에 몇 번 불렀는지(ai_usage)는 한도를 지키기 위해 따로 셉니다.

자세한 설계는 DICT.md 에 있습니다.

4. 기사 URL 을 가져올 때

주소를 넣으면 Breeze 서버(server/article)가 그 주소를 대신 받아 HTML 과 그림을 건네줍니다. 브라우저가 직접 부르면 막히기 때문입니다(CORS). 이 서버는 받은 것을 저장하지 않고 그대로 넘겨주기만 합니다. 본문 추출은 내 기기의 브라우저가 하고, 여기에 AI 를 쓰지 않습니다.

5. 영어 사전 메타데이터 조회

발음·음성과 영어 뜻을 채울 때, 브라우저가 다음 서비스를 직접 부릅니다. Breeze 서버를 거치지 않으며, 낱말 하나만 갑니다. 한국어 뜻을 받거나 대신 만드는 데에는 쓰지 않습니다.

  • api.dictionaryapi.dev

이 요청들은 각 서비스에 내 IP 주소가 보이게 됩니다 — 웹에서 어떤 주소를 부르든 마찬가지입니다. 그쪽의 기록 정책은 그쪽 소관입니다.

6. 하지 않는 것

  • 광고, 광고 식별자, 추적 픽셀, 분석 SDK — 하나도 없습니다
  • 위치, 연락처, 사진첩, 카메라, 마이크 — 요구하지 않습니다
  • 개인정보를 팔거나, 광고를 위해 공유하거나, 프로파일링하지 않습니다
  • 자동화된 결정으로 이용자에게 불이익을 주지 않습니다

7. 얼마나 두나

  • 기기 안의 것 — 내가 지울 때까지. Breeze 가 알아서 지우지 않습니다.
  • 서버의 것 — 계정이 있는 동안. 계정을 지우면 함께 지웁니다.
  • 로그인 전 무료 횟수 기록은 기기 표시에 묶여 있고, 다른 것과 연결되지 않습니다.

10. 아동

만 14세 미만은 법정대리인의 동의가 있어야 계정을 만들 수 있습니다. 동의 없이 만든 계정을 알게 되면 지웁니다. 로그인 없이 읽고 단어장을 쓰는 것은 나이와 관계없이 할 수 있습니다. 다만 AI·영어 사전 메타데이터 조회와 기사 URL 가져오기는 위에 적은 외부 요청을 사용합니다.

11. 안전하게 지키기

  • 서버와 주고받는 것은 모두 HTTPS 로 암호화됩니다.
  • 단어장 전송에는 HTTPS를 사용합니다. 이전 암호화 보관함은 기존 형식 그대로 보존합니다.
  • 서버의 표는 행 수준 보안(RLS)으로 잠겨 있어, 로그인한 사람은 자기 줄만 읽고 씁니다.
  • 비밀번호를 아예 만들지 않으므로, 새어 나갈 비밀번호도 없습니다.
