# Reader / 단어 상세 정리

## 원인과 변경

- 숙어 판정: `refreshReaderWords()`가 본문 전체를 교체하고 문단 앵커로 스크롤을 되돌렸습니다. 실제 선택 단어 노드가 사라지고, 이미지·지연 단어 생성까지 다시 실행되는 구조였습니다. 이제 단어 하나는 항상 같은 span을 유지하며, 숙어 구성원들이 같은 의미 키를 공유합니다. 판정/삭제 시 의미 키와 색상 클래스만 갱신합니다. 스크롤을 복원해야 할 사건 자체를 없앴습니다.
- mini pill: 44px짜리 필이 위에 들어가는지만 보던 조건을, 확장될 카드의 공간을 고려하는 조건으로 바꿨습니다. 안전 영역과 하단 컨트롤을 제외하고, 아래에 충분한 공간이 있으면 아래, 위에 충분하면 위, 둘 다 부족하면 더 넓은 쪽을 택합니다. 같은 조회 중에는 방향을 고정합니다. 본문을 밀거나 자동 스크롤하지 않습니다.
- 내보내기: Blob 다운로드 링크만 만들던 웹 경로에, iOS 임시 CSV 파일 → 시스템 공유 시트 경로를 추가했습니다. 모바일 브라우저는 파일 공유가 가능하면 공유 API를, 그 외에는 다운로드를 사용합니다. CSV BOM/따옴표/쉼표 처리를 유지하며, 공유 취소는 오류로 알리지 않습니다. iPad 팝오버 위치도 지정합니다. 네이티브 동작은 앱 재빌드가 필요합니다.
- 진행률: 책 목록의 반올림과 Home pill의 버림이 달랐습니다. 동일한 저장 위치를 같은 함수로 표시하며, 실제 완료 전에는 100%가 되지 않게 했습니다.
- 설정: 로그인된 계정의 로그아웃/계정 삭제 영역을 복구·기기 연결·자료 내보내기 아래로 옮겼습니다. 인증/삭제 동작은 그대로입니다.
- Home ↔ Reader: 문자를 확대·찌그러뜨리는 변형 대신 둥근 표면의 경계와 짧은 흐림을 애니메이션합니다. Reader의 홈 버튼은 이를 역방향으로 실행합니다. 동작 줄이기 설정에서는 바로 이동합니다.

## 알림 정리

제거: “단어장에서 뺐어요”, “Original mode / Text mode”, 조회창에 이미 표시되는 사용량 소진의 중복 알림.

유지: 발음 재생 실패/미지원, 로컬 저장 실패, 복구키 저장 요청, 기기 연결 결과, 책 열기·파일 가져오기 실패. 사용자가 상황을 알거나 대응해야 하는 알림입니다. 조회 상태와 오류는 조회창 안에 남깁니다.

## 다음 상세 카드 디자인 제안

목표는 작은 필을 펼쳤을 때 다른 장소의 큰 팝업이 나타나는 것이 아니라, 같은 뜻을 가진 작은 표면이 더 많은 정보를 드러내는 것입니다.

1. 맨 위 한 줄: 표제어 · 발음 · 접기. 큰 제목과 넓은 상하 여백을 줄입니다.
2. 핵심은 한국어 뜻 한 번. 현재 뜻과 동일한 “저장된 뜻” 칩을 반복하지 않습니다. 다른 뜻이 있을 때만 “다른 뜻 N개”를 펼칩니다.
3. 별 1/2/3은 한 줄의 작은 선택 컨트롤. 색칠과 단어장에서 빼기는 보조 메뉴로 이동합니다.
4. 예문은 두세 줄만 먼저 표시하고 필요할 때 펼칩니다. 영어 뜻이 없으면 “찾지 못했어요”라는 빈 섹션 자체를 만들지 않습니다.
5. 첫 확장 높이는 약 320–420px를 목표로 하고, 상세 정보가 많으면 카드 내부만 스크롤합니다. 위쪽 단어는 아래로, 아래쪽 단어는 위로 확장합니다.
6. pill의 맞닿은 변을 고정하고 폭·높이·모서리를 변화시킵니다. 배경 표면을 먼저 넓히고 내용을 짧게 나타내며, 글자는 늘려서 변형하지 않습니다. 닫을 때도 같은 선택 자리로 돌아갑니다.

후속 변경으로 상세 카드 정보 재배치와 mini pill 확장·접기 morph까지 적용했습니다. 자세한 내용은 2026-09-22-word-morph-home-stability.md에 기록했습니다. 기존 저장 뜻·난이도·예문 데이터는 유지합니다.

## 검증

- `npm test`: 통과(타입·구조·lookup 생명주기·의미 삭제·동기화·문장·EPUB·단어 생성 등).
- `npm run test:home-ui`: 통과(Home/Reader, 5개 화면 폭, light/dark, 진행률, 단어장 내보내기).
- `node tests/verify-reader-notifications-browser.mjs`: Chromium/WebKit 통과.
- `node tests/verify-word-presentation-browser.mjs`: Chromium/WebKit 통과.
- `npm run test:reader-refinements`: Chromium/WebKit에서 본문 3개 깊이의 DOM·스크롤 유지, 화면 가장자리 배치, 홈 복귀/재개, 진행률 소수점, 네이티브 CSV 요청·취소·다운로드 통과.
- Xcode iOS Simulator 대상 코드 빌드: 성공. 공유 시트의 실제 iPhone 파일 저장은 아직 검증하지 않았습니다.
- `git diff --check`: 통과. 커밋·푸시 없음.

네이티브 공유 구현은 Apple의 [UIActivityViewController](https://developer.apple.com/documentation/uikit/uiactivityviewcontroller) 파일 공유 경로를 사용합니다.
