## Change and ownership

`refreshStudySetsEntry()` skips the hidden `.view` Memory host. Entry still reads
durable storage; an open directory uses its owner's already decoded state.
Visible background Memory during creation continues to refresh while typed input
is retained. `studySetsReturnHomeFocus()` no longer rebuilds the hidden list before
navigation makes it visible. Hidden startup also waits for the first visible entry.

Both directory renderers use a shared, UI-local summary of the validated set:
active card count and session index/queue length. The old per-set `view()` copied
and validated the entire collection; the new summary does neither. There is no
storage cache, new dirty-state owner, or new trusted core API. Mutation reads,
corruption/future-version checks, commit normalization and concurrent-write
verification in `scripts/core/study-sets-storage.js` remain byte-identical.

The existing 65 core/storage/UI assertions are unchanged and passed. The trusted
touch fixture now calls `readStudySets()` explicitly before its initial commit;
it no longer relies on an invisible startup render to perform that read. Its
strict gesture, geometry and persistence assertions are unchanged. The browser
measurement also asserts real cross-tab storage delivery, deferred hidden DOM,
reload, failed write retaining the revealed answer, and stale retry loading the
other tab's latest card without grading it.

## Measurements

[before.json](before.json) and [after.json](after.json) contain every sample.
Linux system Chromium **151.0.7922.173**, viewport 390×844, no CPU throttling,
100 captured cards and 100 frozen queue cards per set. Each operation has 5 warmups
and 20 measured samples. Before serves the exact base UI file over the same local
server and instruments the same core `normalize()` entry. Response time is the
synchronous mutation/render or return-to-Memory call, including layout work it
forces; it does not include a guaranteed next painted frame.

Return-to-Memory hidden rebuilds are 1 → 0 and total list rebuilds 2 → 1 in
all sizes. The remaining five reveal normalizations are durable read, mutation,
commit decode, commit normalize, and visible study view. List entry still performs
one full validation, so overall collection work remains O(C); only the repeated
O(S×C) list work is removed. Small-set timings are noisy and do not establish a device speedup.
These are synthetic browser observations, not physical iPhone/iPad performance,
CPU profiling, heap-allocation measurements, or a promise of speedup.
