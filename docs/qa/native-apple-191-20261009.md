## Implementation and deterministic evidence

- AuthenticationServices Apple request: fresh 32-byte random nonce, SHA-256
  challenge, UUID state, request/controller-bound response, issuer/native
  audience/subject/expiry/digest checks. Supabase performs signature validation.
- Existing Supabase JS 2.112.3 client, existing session key and wordbook sync;
  `signInWithIdToken({provider:'apple',token,nonce})`. No email-only client linking.
- Cancellation gates fetch completion, delayed JSON and the final session write.
  A successful synchronous session write commits login; ordinary auth listeners
  then accept it and start account-owned sync. No token/nonce diagnostic logging.
- 27 deterministic JS auth cases; Chromium actual bundled SDK covers web Apple,
  web Google, native Google, native Apple, session persistence/reload, native
  logout/relogin, OS cancellation/error, late OS reply, delayed network, delayed
  JSON and delayed final SDK session write. Cancelled requests cannot persist
  sessions or alter the fixture wordbook. Fixtures retain the same auth user ID.
- macOS CI executes production Foundation token/callback policy checks and builds
  App/Share for Simulator without signing. This establishes compilation, not live
  Apple consent or signing. Chromium is available locally; WebKit runs in CI.
- App/Share Debug/Release are 1.9.1, baseline counter 253. Cloud tests reject
  malformed counters, missing target settings and version drift. Icon/onboarding,
