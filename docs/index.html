Breeze Refactored

📖 읽기 좋은 문서: https://metrobummin.github.io/breeze/docs/ 이 저장소의 .md 문서들을 폰에서도 읽히게 구운 것입니다. 목차가 옆에 붙고, 브라우저에서 인쇄(⌘P)하면 PDF 로 저장됩니다. 내용은 여기 파일과 항상 같습니다 — npm test 를 돌릴 때마다 다시 굽습니다(tools/build-docs.mjs).

기존 breeze/index.html 단일 파일을 기능별 파일로 분리한 버전입니다. 원본 프로젝트는 수정하지 않았습니다.

읽을거리를 파일에만 의존하지 않도록 방향을 넓히는 중입니다 — ROADMAP.md.

  • 홈은 두 줄입니다. Casuals(기사·스레드·짧은 글)는 옆으로 넘기고, Books(원서·PDF·EPUB)은 아래로 봅니다. 줄마다 라이브러리와 +가 하나씩 있고, 두 줄은 각자 자기 줄에서 마지막에 읽던 것을 테두리로 기억합니다 — 기사를 한 편 봤다고 읽던 원서 표시가 사라지지 않습니다. 그래서 "이어서 읽기" 칸이 따로 없습니다.
  • 붙여넣기는 글의 모양을 먼저 알아봅니다. 깃허브에서 남의 README를 긁어오면 마크다운이 오고, 페이지 소스를 긁어오면 HTML이 옵니다. 예전에는 전부 평범한 글로 다뤄서 ## Getting started나 |---|---|가 본문에 그대로 남았습니다. 이제 마크다운은 제목·목록·표·인용·코드로 옮기고(배지·링크 주소·HTML 주석·YAML 머리말은 버립니다), HTML은 기사 URL과 같은 추출기를 태웁니다. 표는 격자를 그리지 않고 한 행을 한 줄로 상자에 담습니다 — 격자는 폰에서 옆으로 넘치고, 문단으로 풀면 낱말이 어느 칸 것인지 사라지니까요. 코드는 줄바꿈을 그대로 두되 사전을 걸지 않습니다(npm install이 단어장에 쌓이면 안 되니까요). 구조 기호가 없는 평범한 글과 X 스레드는 예전 그대로 다룹니다.
  • +는 그 줄에 넣을 수 있는 것만 엽니다. Casuals는 붙여넣기·기사 URL 두 가지, Books는 파일 하나뿐이라 곧장 파일 고르기로 갑니다. 상단바의 +만 셋을 다 보여줍니다.
  • 기사 URL은 본문과 사진을 골라 옵니다. 추출은 브라우저의 DOMParser로 하고, AI를 쓰지 않습니다. 사진은 넣는 순간 기기에 담기므로 비행기 안에서도 그대로 뜨고, 읽을 때마다 그 매체 서버에 발자국을 남기지 않습니다. 대표 사진은 Casuals 카드의 표지가 됩니다. 서버(server/article)가 하는 일은 CORS를 넘겨 HTML과 그림을 건네주는 것뿐입니다. 로그인·결제가 필요한 기사는 아직 못 가져오며, 그럴 땐 그렇다고 말하고 붙여넣기를 권합니다.
  • 카드를 꾹 누르면 제목·표지를 고치는 시트가 열리고, 지우기도 여기 있습니다. 지울 때는 이 기기에서만과 모든 기기에서를 물어봅니다 — 되돌릴 수 없는 쪽이 기본이면 안 되니까요.
  • 짧은 글은 넣는 즉시 서버에도 올라갑니다. 폰에서 담고 노트북에서 읽는 게 Casuals가 있는 이유인데, 그러려면 Sync 창을 열어 책마다 올리기를 눌러야 했습니다. 원서는 수백 KB라 그대로 수동입니다.
  • 기사 사진은 기기 간에도 따라옵니다. 사진 자체가 아니라 사진의 주소를 올리고, 받는 기기가 스스로 한 번 받아 담습니다 — 남의 사진을 서버에 다시 쌓지 않으면서 결과는 같습니다. (EPUB 삽화는 받아 올 곳이 없어서, 새 기기에서 원본 파일을 다시 연결해야 합니다.)
  • 기사에는 연결할 원본 파일이 없습니다(원본 모드는 PDF·EPUB 전용). 대신 제목 아래에 원문으로 가는 링크를 둡니다 — 영상·인터랙티브 도표는 거기서 봐 주세요.
  • 무료 고전 5종(셜록 홈즈, 이상한 나라의 앨리스, 위대한 개츠비, 오만과 편견, 프랑켄슈타인)이 함께 들어 있습니다. 카드를 누르면 평범한 EPUB 반입 경로를 그대로 타므로 원본과 글자 모드가 모두 따라옵니다.
  • 켜고 끄는 집중 모드는 없앴습니다. 대신 읽는 방향이 신호입니다 — 아래로 읽어 내려가면 상단바가 저절로 걷히고, 위로 올리거나 글머리에 닿으면 돌아옵니다. 화면에 남는 것은 오른쪽 아래 동그란 단추 둘(Aa, 원본↔글자)뿐이고, 이 둘은 자리를 옮기지 않습니다. 글 폭은 스크롤과 묶지 않았습니다 — 읽는 도중 줄바꿈이 흔들리면 보던 자리를 놓치기 때문입니다. 좌우 여백은 Aa 안에서 세 단계로 고릅니다.
  • 사전은 AI 하나에 걸었습니다. 낱말을 누르면 AI 가 그 문장을 보고 뜻과 "이 문장에서 어떻게 쓰였나"를 한 번에 답합니다. 그 답은 누른 사람 기기에만 남고, 같은 문장에서 다시 누르면 0원·즉시 뜹니다. 뜻을 서버에 쌓아 두고 함께 쓰는 공용 사전은 만들다가 접었습니다 — 화면 두 줄 중 무료 사전으로도 되는 줄만 캐시하면서, 정작 문맥에 안 맞는 뜻을 확신 있게 내놓을 새 경로를 하나 만들었기 때문입니다. 무료 사전은 이제 답을 두고 다투지 않고 발음·영어 뜻을 채우거나, 로그인 전·한도 초과·오프라인일 때 자리를 지킵니다. 서버에 남는 것은 뜻이 아니라 사람이 무엇을 했는가(뜻을 고쳤다, 다른 뜻을 다시 물었다)이고, 읽던 문장은 되돌릴 수 없는 지문으로만 남습니다 — DICT.md.
  • 뜻은 그 자리에서 고칩니다. 예전에는 AI 박스 아래에 파란 뜻 칸이 하나 더 있어서 같은 뜻이 화면에 두 번 적혀 있었고, 고치는 건 아래 칸에서만 됐습니다. 이제 위에 뜬 뜻을 누르면 바로 고쳐지고 그게 단어장에 들어갑니다. 한번 손으로 고친 뜻은 AI 가 덮지 않습니다. 기다리는 동안에는 점 세 개가 아니라 돌풍 세 줄기가 지나갑니다.
  • 첫 화면에서 받는 외부 라이브러리는 Supabase 하나(212KB)뿐입니다. PDF·EPUB 라이브러리(418KB)는 파일을 처음 열 때 받고, 단어장은 CSV로 내보내므로 xlsx 881KB가 필요 없습니다. 파일로 들고 다니던 사전 300개(73KB)도 지웠습니다 — 문맥을 안 보고 온 뜻이라, 문맥 뜻을 파는 앱의 맨 앞에 둘 층이 아니었습니다. 예전에는 1.5MB를 모두가 매번 받았습니다.
  • 수능·모의고사 문항 분리와 기출 Shorts 화면은 떼어 두었습니다(동작은 하지만 앱에 연결되어 있지 않습니다). 규칙과 되살리는 순서는 modules/exam-shorts/README.md.

주요 구조

  • 목차 버튼과 목차 시트를 화면에서 제거했습니다.
  • CSS를 화면 책임별로 6개 파일로 분리했습니다.
  • JavaScript를 저장소, 라이브러리, 반입기, 사전, 리더, 설정, 동기화로 분리했습니다.
  • PDF와 EPUB은 원본과 글자 모드를 자유롭게 전환할 수 있습니다.
  • 원본 파일은 별도 IndexedDB 저장소에 보관하며 서버 책 동기화에 포함하지 않습니다.
  • 글자 문단마다 원본 PDF 페이지·페이지 내부 위치 또는 EPUB 장·요소 위치를 연결합니다.
  • PDF 원본은 PDF.js 캔버스와 페이지 비율 단어 좌표 지도를 사용합니다. 단어를 한 번 누르면 같은 좌표로 사전과 하이라이트가 열려, 패널이 생겨 페이지 폭이 바뀌어도 범위가 밀리지 않습니다.
  • 글자를 하나씩 따로 넘겨주는 PDF도 같은 기준선끼리 되붙여 진짜 단어로 읽습니다. 예전에는 낱글자가 단어가 되어 저장한 h가 온 페이지에 밑줄을 그었습니다.
  • 원본 위치 지도는 걸러낸 페이지를 뺀 순번이 아니라 실제 PDF 페이지 번호를 씁니다. 이미 넣어 둔 책은 같은 파일을 한 번 더 끌어다 놓으면 지도만 새로 만들고 진행도와 단어장은 그대로 둡니다.
  • 사전 패널이 열리고 닫혀 읽는 폭이 바뀌어도 보던 줄이 제자리에 남습니다.
  • EPUB 원본은 스크립트와 위험 요소를 제거한 뒤 샌드박스 안에서 출판사 스타일을 표시합니다.
  • 글자 모드는 문서 자체의 확실한 구조 단서만 반영하고, 애매한 부분은 평범한 본문으로 둡니다.
  • 전권 AI 조판 클라이언트·서버 함수·캐시는 제거했습니다. 문맥 사전 AI는 별도 기능이라 유지합니다.
  • IndexedDB 이미지 이름 변경 완료 대기, 책 삭제 tombstone, Supabase 삭제 재시도와 겹친 동기화 요청 처리를 정리했습니다.
  • 동일한 책을 다른 파서 버전으로 넣어도 내용 지문으로 서버 사본을 찾습니다.

원본 파일과 동기화

  • 새 PDF/EPUB은 반입할 때 원본 Blob과 추출된 글자를 서로 다른 로컬 저장소에 넣습니다.
  • 서버 책 동기화에는 추출된 글자, 보수적인 블록 정보, 작은 위치 지도, 파일 형식 메타데이터만 포함됩니다.
  • 다른 기기에서 서버 책을 받은 뒤 원본 모드를 쓰려면 같은 원본 파일을 한 번 다시 연결해야 합니다.
  • 기존 책도 원본 모드에서 파일을 다시 고르면 내용 지문을 검사한 뒤 진행도와 단어장을 유지합니다.
  • 예전 책 ID로 저장된 원본도 파일 해시로 다시 찾아 현재 책 ID에 연결하며, 읽는 중에는 서버 삭제 표시가 로컬 원본을 지우지 않습니다.
  • 진행도는 서로 다른 화면 높이를 섞지 않고 PDF 페이지·EPUB 장·글자 문단의 논리적 위치로 계산합니다.
  • DRM EPUB과 스캔 PDF의 단어 클릭/OCR은 지원하지 않습니다. 스캔 PDF는 원본 화면으로 읽을 수 있습니다.

실행

정적 파일 서버에서 이 폴더를 열면 됩니다. file://로 직접 열면 브라우저의 파일·네트워크 정책 때문에 PDF/EPUB 기능이 제한될 수 있습니다.

python3 -m http.server 8765

그 뒤 http://127.0.0.1:8765/를 엽니다.

Node.js가 있으면 외부 패키지 없이 구조 검사를 실행할 수 있습니다.
