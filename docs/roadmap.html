Breeze 로드맵

제품의 중심

Breeze는 파일 형식 자체보다 읽기 → 문맥 뜻 → 내 단어장의 흐름에 집중합니다. 기능을 많이 쌓기보다, 읽던 자리가 흔들리지 않고 개인 데이터의 경계가 분명한 리더를 먼저 출시합니다.

현재 출시 범위

영역현재 상태
PDF·EPUB 글자/원본 읽기사용 가능
PDF 원본 확대− / + 단추, 핀치 확대는 사용하지 않음
붙여 넣은 글사용 가능
공개 페이지 기사 URL 가져오기사용 가능, 사이트 조건·권리 범위 안에서만
문맥 사전·단어장사용 가능
문장 전체 설명로그인 후 하루 5회
단어장·위치·책 텍스트 동기화사용 가능, 현재 E2EE 아님
iOS Capacitor 셸있음
Android 네이티브 셸아직 없음

출시 전: 안정화

  1. 원본 파일 다시 연결
    • 같은 PDF/EPUB인지 원본 파일 해시를 먼저 확인하도록 보완합니다.
    • 현재의 텍스트 지문 비교는 이전 데이터 호환용 보조 경로로 둡니다.
  1. 읽기 화면 안정성
    • ResizeObserver 경고가 실제 앱 오류처럼 빨간 화면에 표시되지 않게 고칩니다.
    • PDF 확대 버튼, 진행 줄, 상단바가 iOS 홈 화면 웹앱에서 안정적으로 동작하는지 실제 기기로 확인합니다.
    • Android 8–9에서는 기본 읽기·단어장·로그인 흐름을 우선 검증하고, 대용량 PDF의 고성능을 약속하지 않습니다.
  1. 문장 설명 신뢰성
    • 한국 시간 기준 한도 안내, 중복 요청 방지, 요청 시간 초과 처리를 다듬습니다.
  1. 첫 경험과 출시 준비
    • 빈 라이브러리, 권한·로그인 안내, 오류 문구, 대표 목업을 정리합니다.
    • iOS TestFlight와 Android 내부/비공개 테스트를 통해 실제 기기에서 먼저 확인합니다.

출시 뒤 우선순위

1. 동기화의 선택권과 개인정보

현재 동기화는 편하지만 종단간 암호화가 아닙니다. 다음 큰 결정은 기능 추가가 아니라 사용자가 무엇을 서버에 맡길지 고르는 방식입니다.

  • 단어와 학습 상태는 기본 동기화로 유지할지 결정합니다.
  • 책 텍스트·제목·진행도·문맥 예문은 선택형 암호화 동기화 금고로 분리하는 방안을 검토합니다.
  • 이 기능은 사용자가 정한 동기화 암호로 기기에서만 암복호화해야 합니다. 이메일·사용자 ID·앱 안의 고정 salt만으로 만든 키는 서버도 재현할 수 있어 E2EE가 아닙니다.

이 설계는 아직 구현하지 않았습니다. 출시 직전에 서둘러 넣지 않고, 복구·기기 추가·암호 분실 안내까지 함께 설계한 뒤 진행합니다.

2. 단어 복습 MVP

Anki의 원리(간격 반복)는 참고하되, Anki 코드나 앱을 끌어오지 않습니다.

  • 단어별 다음 복습일, 간격, 정답/실패 횟수만 둡니다.
  • 하루 새 단어와 복습 수에 작은 상한을 둡니다.
  • 다시 / 어려움 / 알겠음 정도의 간단한 선택으로 시작합니다.

단어가 500개, 1,000개가 되어도 한꺼번에 몰아 보여 주지 않는 것이 핵심입니다.

3. Casuals의 입력 마찰 줄이기

RSS는 먼저 원문 링크 카드와 제목·요약·표지를 편하게 받아 보는 용도로 검토합니다. 본문을 자동 저장하거나 유료·로그인 페이지를 우회하는 기능은 기본값으로 만들지 않습니다. 출처별 약관과 저작권을 확인하고, 허용되거나 명시적으로 라이선스된 소스부터 좁게 지원합니다.

지금 보류하는 것

  • 유료 기사 우회, 로그인한 타사 페이지에 스크립트 주입
  • 전체 책 본문을 AI로 재조판하는 기능
  • DRM EPUB 해제, 스캔 PDF OCR
  • 기출 Shorts와 사전 답 사전생성 기능의 재연결
  • 네이티브 PDFKit/Android 뷰어로의 전면 교체

이들은 불가능해서가 아니라 출시 품질, 권리, 유지보수 비용에 비해 지금의 핵심 흐름을 더 좋게 만들지 않기 때문에 보류합니다.
